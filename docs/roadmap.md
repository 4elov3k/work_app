## Точки роста по фичам

### 1. Документы
- **`accounting-mcp`** — отдельный MCP-сервис для управления документами голосом/текстом через Hermes, уже работает (см. `docs/accounting-mcp-service.md`, `docs/tz-hermes-accounting-mcp.md`). Расширять операции вслепую не стоит — нет конкретных сценариев. ~~Логирование неподдерживаемых вызовов~~ — сделано и смерджено (2026-08-20): `mcpserver.AddReceivingMiddleware` логирует `tools/call` с несуществующим именем инструмента. Осталось: подождать, пока в логах наберётся 2-3 повторяющихся реальных кейса, и только тогда расширять под них.
- **`docparse`** — распознавание сканов договоров сейчас извлекает номер/дату/кандидатов ИНН. Кандидаты на расширение: акты от контрагентов (для сверки), счета от контрагентов (для учёта расходов). Для каждого типа нужно до старта: (1) реальные сканы, минимум 3-5 образцов — без них паттерны извлечения будут гадательными, как было с "02Декабря" без пробела в текущем `ExtractContractFields`; (2) список полей на извлечение (номер/дата уже есть общим паттерном; для актов/счетов дополнительно — сумма, контрагент, статьи); (3) тесты на реальном OCR-тексте по образцу `docparse/extract_test.go`. Не начинать без образцов.

### 2. Redmine — приоритетное направление

- `redmine_project_control_events` — таблица с событиями (`control_cut`, `report_date`), статусами (`planned`/`sent`/`skipped`), циклами по типу проекта
- В этой сессии починена главная опасность (каскадное удаление → пометка `skipped`, история не теряется) и рассинхрон между дашбордом и страницей проекта

### 3. Звонари
- **Пагинация звонков** добавлена ранее (50/страница) — на реальных данных видели 781 звонок у одного звонаря за 2 недели, это ещё в пределах нормы. Не переходить на виртуализацию (`react-window`/`@tanstack/react-virtual`) или серверную пагинацию заранее — решение принимать по факту, когда у кого-то объём вырастет на порядок (~5000+ звонков), а не сейчас.
- **GPU-транскрипция** — отдельный ПК с RTX 5070 Ti уже в плане ([[zvonari_gpu_transcription_plan]] в памяти), нативная установка под Windows. Не код-задача, ждёт железа.

## Гигиена (продолжать практику)

- Личные/клиентские документы (счета, акты, сканы) не должны попадать в корень репозитория — `.gitignore` теперь блокирует секреты и `client_secret*.json`, но общего паттерна на "документы в корне" нет. Если привычка попадать файлам в корень повторится — стоит завести отдельную несинхронизируемую папку по умолчанию (например, `~/dev/work_app_local_files/`, уже используется) и не хранить рабочие файлы рядом с репозиторием вовсе.
- `import/` и `export/` теперь оба в `.gitignore` — это рабочие папки для парсинга/выгрузки документов, не для истории git. Если появится третья подобная папка — сразу добавлять в `.gitignore`, не дожидаясь, пока туда попадут реальные клиентские данные.
