# Звонари — итерация улучшений (без переписывания)

Задание для Claude Code. Работаем внутри существующей архитектуры: OnlinePBX → CDR → Hermes Whisper (8645) → Hermes Analytics (8646) → агрегаты на `/zvonari`.

## Правила итерации

- Никаких смен фреймворка, схемы данных «с нуля» или переезда очередей. Только аддитивные изменения.
- Миграции БД — только `ADD COLUMN` с дефолтом и `CREATE INDEX`. Ничего не удаляем и не переименовываем.
- Каждая задача — отдельный коммит, работающий сам по себе. Не сваливать в одну пачку.
- Не менять контракт Hermes-сервисов. Всё, что нужно, добавляем на своей стороне.
- Перед каждой задачей — прочитать код, который она трогает, и написать в ответе, какие файлы будут изменены.

## Этап 0. Разведка (сделать первым, ничего не менять)

Составить и вывести карту:

1. Модель звонка: все поля, статусы транскрибации, поле outcome и его допустимые значения (закрытый список из 13).
2. Как устроены фоновые задачи синка: где хранится состояние, как работает пауза/резюме, что отдаёт статус-эндпоинт.
3. Все эндпоинты `/zvonari`: агрегат за период, список звонков, ретрай транскрибации, ре-анализ, отчёт Hermes, CSV.
4. Пагинация звонков (50/стр.) — серверная или клиентская.
5. Где формируется промпт для `hermes_call_analytics` и где зашита версия регламента IQ-200 v1.2.
6. Как выбирается GPU-бокс vs CPU и сохраняется ли где-то, на чём фактически прошла транскрибация.

Вывести короткий отчёт по каждому пункту, дальше идти по приоритетам.

# P0 — дешёвое и болезненное

## 1. Единый статус конвейера вместо трёх разрозненных кнопок

**Проблема.** Прогресс-бар есть только у синхронизации. Транскрибация и анализ идут вслепую: пользователь жмёт «Анализировать» и не понимает, началось ли что-то и когда закончится.

**Сделать.**
- Расширить существующий статус-эндпоинт до массива стадий: `sync`, `transcribe`, `analyze`. У каждой — `state` (idle/running/paused/failed), `done`, `total`, `errors`, `started_at`, `finished_at`.
- На фронте один блок «Состояние обработки» с тремя полосами вместо одной. Полоса неактивной стадии — серая, не скрытая, чтобы был виден весь путь.
- Считать `total` для transcribe/analyze как число звонков периода, подходящих под стадию, а не как «сколько поставили в очередь».

**Готово когда:** запустив «Анализировать», видно `проанализировано 340 из 1204, ошибок 12` без перезагрузки страницы.

## 2. Автообновление, пока что-то работает

**Проблема.** Счётчики и KPI не обновляются сами, нужно жать F5.

**Сделать.**
- Пока хотя бы одна стадия в `running` — опрашивать статус раз в 3 секунды; счётчики и KPI перечитывать раз в 15 секунд.
- Когда всё `idle` — опрос прекращать полностью.
- Останавливать опрос при `document.hidden`, возобновлять на `visibilitychange`.
- Экспоненциальный backoff при ошибках статус-эндпоинта, максимум 30 секунд.

**Готово когда:** вкладка с активным синком сама доводит прогресс до 100% и подтягивает новые KPI; неактивная вкладка не долбит бэкенд.

## 3. Защита от дублей запуска

**Проблема.** Две вкладки или двойной клик = два конвейера на один период.

**Сделать.**
- Серверный лок по ключу `(тип_задачи, from, to)`. Повторный запуск возвращает 409 и текущий статус, а не новую задачу.
- Кнопка дизейблится на время своей стадии и показывает, что именно идёт.
- На 409 фронт не показывает ошибку, а просто подхватывает уже идущую задачу.

## 4. Подтверждение для «Перетранскрибировать на GPU»

**Проблема.** Кнопка молча гоняет заново **все** звонки периода. Это самая дорогая операция в системе, и она в один клик рядом с безобидными.

**Сделать.**
- Добавить в модель транскрипта поле `engine` (`cpu` / `gpu`) и `transcribed_at`, заполнять при каждой транскрибации.
- Перед запуском показывать подтверждение с числом: «Будет пересчитано N звонков (из них M уже на GPU). Примерная длительность ~T». Оценку T считать по средней длительности прошлых прогонов.
- Добавить чекбокс «Только те, что делались на CPU» — включён по умолчанию. Полный прогон остаётся, но становится осознанным выбором.
- Кнопку визуально отделить от остальных (вторичный/danger-стиль).

**Готово когда:** случайно перегнать 5000 звонков одним кликом невозможно.

## 5. Состояние страницы в URL

**Проблема.** Перезагрузка или отправка ссылки коллеге теряет период, сортировку, раскрытого звонаря и фильтр по чипу.

**Сделать.** Синхронизировать в query-параметры: `from`, `to`, `sort`, `dir`, `zvonar`, `outcome`, `q`, `page`. При загрузке — восстанавливать состояние из URL. Менять URL через `replaceState`, чтобы не засорять историю.

**Готово когда:** ссылка на раскрытого звонаря с фильтром «Срыв на шаге 1» открывается у другого человека в том же виде.

## 6. Разбор ошибок вместо одной красной строки

**Проблема.** «Повторить неудачные» гребёт `failed`, `no_recording` и `pending` в кучу. `no_recording` ретраем не лечится — записи просто нет. `pending` вообще не ошибка, и его ретрай может продублировать работу.

**Сделать.**
- Разделить статусы на терминальные (`no_recording`, и другие, где ретрай бессмыслен) и восстановимые.
- Под блоком синхронизации — сводка ошибок по причинам: `нет записи — 34`, `таймаут Whisper — 7`, `analytics 5xx — 3`, каждая строка кликабельна и фильтрует список звонков.
- «Повторить неудачные» по умолчанию берёт только восстановимые. Терминальные — отдельным явным действием.
- Хранить в звонке `last_error` (текст) и `error_kind` (enum), чтобы группировка работала.

## 7. Индикатор здоровья внешних сервисов

**Сделать.** Один эндпоинт `/zvonari/health`, который пингует `hermes_call_transcribe:8645`, `hermes_call_analytics:8646` и GPU-бокс с таймаутом 2с и кешем на 30с. В шапке — три точки с тултипом. Если анализ падает, сразу видно, что это не приложение.

# P1 — качество аналитики

## 8. Версионирование регламента оценки

**Проблема.** Регламент правят, а понять, какие звонки оценены старой версией, нельзя. Ре-анализ приходится делать вслепую и целиком.

**Сделать.**
- Поле `analysis_version` в результате анализа (строка вида `IQ-200 v1.2`), заполняется из константы, которая уходит в промпт.
- В фильтрах списка звонков — «версия анализа».
- Массовое действие «Переанализировать всё старее версии X» за период, с подтверждением и числом.
- В KPI добавить (или в сводку под ними) «Оценено устаревшей версией: N».

**Это самая ценная задача блока — делать после P0 первой.**

## 9. Отделить «не распарсилось» от «не проанализировано»

**Проблема.** Если LLM вернула outcome вне закрытого списка из 13 или сломанный формат, это сейчас неотличимо от «анализ не запускался».

**Сделать.**
- Сохранять сырой ответ модели в отдельное поле.
- Валидировать outcome по закрытому списку. Невалидный → статус `parse_failed`, а не `failed` и не `pending`.
- Отдельный счётчик и отдельная кнопка ретрая для `parse_failed` (там помогает просто повтор).

## 10. Прозрачность фрод-детекции

**Проблема.** «Автоответчик (фрод)» — чёрный ящик, а решение основано на длительности плюс модель.

**Сделать.**
- Показывать в карточке звонка, на каком основании поставлен фрод: длительность, признак от модели, цитата.
- Кнопка «Не фрод» на звонке → флаг `fraud_override` + кто и когда поставил. Из KPI такие звонки исключать.
- Собранные override — основа для правки промпта, отдавать их отдельным CSV.

## 11. Аудит ручных операций

Логировать `retranscribe` / `reanalyze` / `retranscribe-gpu`: кто, когда, сколько звонков, какая версия регламента. Показывать последние 20 в свёрнутом блоке внизу страницы. Без этого невозможно понять, почему цифры за период вчера и сегодня разные.

# P2 — удобство интерфейса

## 12. Кликабельные KPI-плитки

Каждая плитка фильтрует таблицу и список звонков: «Не проанализировано» → показать только их, «Срыв на шаге 1» → только их. Активная плитка подсвечивается, повторный клик снимает фильтр. Сейчас плитки декоративные, а это ровно те вопросы, с которыми на страницу и приходят.

## 13. Дорожная карта скрипта — доработка

- Показывать на чипе число и долю (`Шаг 3 · 128 · 24%`).
- Разрешить мультивыбор чипов (фильтр по ИЛИ), сброс — отдельной крестик-кнопкой.
- Чип с нулём — приглушать, но не прятать, чтобы карта не «скакала» между звонарями.

## 14. Список звонков

- Дебаунс поиска 300 мс, поиск не сбрасывает выбранные фильтры и наоборот.
- Показывать «Найдено N» рядом с пагинацией.
- Сортировка по времени и длительности кликом по заголовку.
- Смена страницы не должна схлопывать раскрытые строки без нужды — либо схлопывать явно, либо сохранять.
- Убедиться, что пагинация серверная (см. Этап 0, п. 4). Если клиентская — перевести на серверную, это самая заметная просадка на больших периодах.

## 15. Оптимистичные действия на строке

«Перетранскрибировать» / «Переанализировать» на звонке: инлайн-спиннер в строке, по завершении — обновление только этой строки, без перезагрузки всей таблицы. Ошибка — текстом в строке, не алертом.

## 16. Плеер записи рядом с транскриптом

Если в CDR есть ссылка на запись — простой `<audio controls>` в раскрытой строке звонка. Проверять оценку LLM без прослушивания невозможно, а сейчас для этого надо идти в OnlinePBX.

## 17. Подсветка цитат по шагам

Если `hermes_call_analytics` возвращает фрагменты-обоснования по шагам — подсвечивать их в транскрипте и скроллить к нужному по клику на шаг. Если не возвращает — задачу пропустить, промпт под это в этой итерации не переделываем.

## 18. Мелочи периода

- Явно показать таймзону у полей «С» / «По». Хранить в UTC, отображать в локальной.
- Пресеты: добавить «Вчера», «Эта неделя», «Прошлая неделя», «Этот месяц».
- Запоминать последний период в `localStorage` и подставлять при входе без параметров в URL.

## 19. Экспорт

- CSV на весь период по всем звонарям, не только построчно.
- Экспорт учитывает текущие фильтры (чипы, поиск, версия анализа), а не выгружает всё подряд.

## 20. Таблица на узком экране

Горизонтальный скролл со «липкой» первой колонкой (Звонарь) и липкой шапкой таблицы при прокрутке. Семь колонок на ноутбуке уже режутся.

# Аддитивные изменения БД (сводно)

```
calls / transcripts:
  + engine            text     -- cpu | gpu
  + transcribed_at    timestamptz
  + last_error        text
  + error_kind        text
analysis:
  + analysis_version  text     -- 'IQ-200 v1.2'
  + raw_response      text
  + fraud_override    boolean default false
  + fraud_override_by text
  + fraud_override_at timestamptz
audit_log (новая, если нет):
  id, action, period_from, period_to, affected_count, actor, created_at, meta jsonb

индексы:
  (zvonar_id, started_at)
  (started_at, transcribe_status)
  (started_at, outcome)
  (analysis_version)
```

Все поля nullable или с дефолтом, старый код продолжает работать без изменений.

# Чего в этой итерации не делаем

- Не переезжаем на Celery/RQ/Kafka, если сейчас самописные фоновые задачи и они работают.
- Не переделываем промпт IQ-200 и не трогаем список из 13 исходов.
- Не вводим роли и права.
- Не делаем вебсокеты — поллинга из задачи 2 достаточно.
- Не трогаем `hermes_sheets_sync`, он к звонарям отношения не имеет.
