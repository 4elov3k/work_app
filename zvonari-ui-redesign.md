# Звонари — структура экрана и визуальный язык

Вторая часть задания для Claude Code. Стек: React + Tailwind + shadcn/ui. Первая часть (`zvonari-improvements.md`) — про логику и данные, эта — про то, как это показано. Задачи здесь ссылаются на неё там, где пересекаются.

## 1. Что конкретно не работает на текущих экранах

Разбор по скриншотам, чтобы было понятно, что чинится и зачем.

**Раскрытая карточка звонаря**

1. В шапке раскрытой строки остались голые числа — `36 · 0% · 0 · 0 · 0 · 67%`. Заголовки колонок в этот момент уже уехали вверх, и что означает `67%` красным, понять невозможно.
2. «Дорожная карта скрипта» занимает ~450px по высоте, чтобы показать пятнадцать нулей. Каждый ноль — это коробка 150×80. Информации ноль, места максимум.
3. Реальный факт про этого звонаря — «36 звонков не проанализировано» — лежит последним чипом в нижнем ряду, самым мелким кеглем, хотя это единственное, что тут вообще есть, и единственное, с чем надо что-то сделать.
4. Всё в одну колонку и в одном визуальном весе: карта скрипта, история отчётов, детализация звонков. Три разные задачи (посмотреть картину / прочитать отчёт / копаться в конкретных звонках) идут подряд, и до звонков надо проскроллить два экрана.
5. Легенда «Прогресс: выполнен / частично / не выполнен / н/д» и подпись `1 → 2 → 3 → 4 → 5 → 6` висят посреди страницы, не привязанные ни к какой колонке. При этом колонка «Прогресс по скрипту» у всех строк пустая (`—`).
6. Кнопки на строке звонка — только иконки (микрофон, звёздочка), без подписей и тултипов. Угадать, что звёздочка это «переанализировать», нельзя.
7. Бейдж «требует внимания» красный, `67%` красное, «ошибка» оранжевая, чипы срывов розовые — четыре разных красных без общей шкалы.

**Шапка и блок синхронизации**

8. Заголовок ~40px + иконка в скруглённом квадрате + подпись-описание сервиса под ним — это чистый шаблон стартового экрана, а страницей пользуются каждый день. Описание «Звонки из OnlinePBX, транскрибация (Whisper локально)...» нужно один раз, дальше оно ест высоту.
9. Четыре действия в ряд с четырьмя разными весами (solid / outline / ghost / ghost) без группировки. Самая дорогая операция — «Перетранскрибировать на GPU» — оформлена самой тихой из всех.
10. Нативные `<input type="date">` рядом с кастомными пилюлями пресетов: разные скругления, разная высота, разный шрифт.
11. Всё на странице — карточка со скруглением 16 и одинаковой тенью, включая карточки внутри карточек. Иерархии нет, поэтому глазу не за что зацепиться.

Пункты 8–11 и есть то самое «нейронисто»: не потому что плохо, а потому что каждый блок сделан по умолчанию, а не под задачу.

## 2. Структура: страница звонаря вместо раскрывающейся строки

**Решение.** Клик по строке ведёт на отдельный роут `/zvonari/:ext?from=&to=`, а не раскрывает аккордеон. Внутри — табы.

Почему роут, а не Sheet или аккордеон: детализация звонков это основное рабочее место, там таблица, фильтры, транскрипты и плеер. Ей нужна вся ширина и своя история навигации. Плюс появляется ссылка, которую можно кинуть в чат («посмотри Смыкову за прошлую неделю») — это же требование из задачи 5 первой части.

Список звонарей остаётся отдельной страницей. Возврат — по крошке, период при переходе сохраняется.

```
/zvonari/100?from=2026-08-27&to=2026-09-02

┌──────────────────────────────────────────────────────────────┐
│ ‹ Звонари   Татьяна Смыкова · 100          27.08 – 02.09  ▾  │ ← sticky
│                                                              │
│  36 звонков   0 проанализировано   0 до шага 6   67% ошибок  │ ← подписи есть всегда
│                                            [Отчёт] [CSV] [⋯] │
├──────────────────────────────────────────────────────────────┤
│  Обзор │ Звонки 36 │ Отчёты 4                                │ ← Tabs
└──────────────────────────────────────────────────────────────┘
```

**Таб «Обзор»** — две колонки на широком экране, одна на узком.

```
┌───────────────────────────────┬──────────────────────────────┐
│ Путь по скрипту               │ Последний отчёт              │
│                               │ 02.09, период 27.08–02.09    │
│ 1 ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓  24     │                              │
│ 2 ▓▓▓▓▓▓▓▓▓▓▓▓  14            │ текст отчёта…                │
│ 3 ▓▓▓▓▓▓  7                   │                              │
│ 4 ▓▓▓  3                      │ ─────────────────────────    │
│ 5 ▓▓  2                       │ Ещё 3 отчёта →               │
│ 6 ▓  1                        │                              │
│                               │                              │
│ Вне скрипта                   │                              │
│ Фрод 2 · Нет потребности 4    │                              │
│ Не проанализировано 36        │                              │
└───────────────────────────────┴──────────────────────────────┘
```

Воронка вертикальная, а не цепочка чипов со стрелками. Скрипт — это отсев, и вертикальные полосы убывающей длины показывают отсев сразу, без чтения цифр. Пятнадцать коробок по горизонтали этого не делают. Стадии с нулём не рисуются вовсе — вместо них строка «Шаги 3–6: никто не дошёл».

Клик по строке воронки → переход на таб «Звонки» с уже наложенным фильтром.

**Таб «Звонки»** — на всю ширину: панель фильтров, таблица, пагинация. Ничего сверху, сразу работа.

**Таб «Отчёты»** — текущий отчёт + история списком. Сейчас история спрятана в `<details>` посреди страницы, здесь у неё своё место.

**Пустое состояние обзора.** Если 36 звонков и 0 анализа — не рисовать пустую воронку. Показать одну строку и действие: «36 звонков ждут анализа» + кнопка «Проанализировать период». Пустой экран — это приглашение нажать, а не сетка нулей.

## 3. Визуальное направление

### Концепция

Это не дашборд. Это **журнал разговоров**: диспетчерская таблица, где строка — звонок, а звонок — это время, длительность, номер и то, как далеко ушёл разговор. Всё оформление должно работать на плотное чтение таблицы, а не на презентацию цифр.

Одна смелость на весь интерфейс — **дорожка скрипта** (см. ниже). Всё остальное держим тихим.

### Дорожка скрипта — фирменный элемент

Шесть сегментов подряд, каждый — шаг регламента. Один компонент, три размера:

```
в строке звонка (h-1.5)   ▪▪▪▪▫▫
в шапке звонаря (h-2.5)   ▪▪▪▪▪▫  агрегат: доля дошедших
в KPI периода (h-4)       ▪▪▪▫▫▫
```

Цвет сегмента — из статусной шкалы (выполнен / частично / не выполнен / н/д). Тултип на сегменте: название шага и вердикт. Это единственный элемент, который заслуживает узнаваемости, потому что он и есть суть продукта. Легенда переезжает в поповер по иконке в заголовке колонки, а не висит отдельной строкой.

Пока `Прогресс по скрипту` пуст (`—`) — рисовать серую дорожку `▫▫▫▫▫▫`, а не прочерк. Так видно, что данные ожидаются, а не что их не бывает.

### Токены

Работать через существующие CSS-переменные shadcn в `globals.css`. Не заводить второй набор цветов и не хардкодить hex в компонентах.

```
--background   #FBFBFA   тёплая бумага, не чистый белый
--foreground   #16211C   тёмно-зелёные чернила вместо #111
--muted-fg     #6B7671
--border       #E3E6E2   волосяная линия
--primary      #2F6F4E   существующий зелёный, только для основного действия и бренда
--accent-bg    #EEF3EF   подложка выделения

статусы (одна шкала, используется и в дорожке, и в бейджах, и в числах):
--ok           #3F8F5F
--partial      #C08419
--fail         #BE4A3F
--na           #C4C9C4
```

Правило: зелёный больше не красит иконки, фон шапки и подложки заголовков. Он остаётся у primary-кнопки и у статуса «выполнен». Сейчас он везде, поэтому не значит ничего.

Красный тоже один. `требует внимания`, `67%`, `ошибка`, чип срыва — все берут `--fail`, различаются только насыщенностью подложки (сплошная заливка только у бейджа, у остальных — 8% тинт).

### Типографика

Две гарнитуры с ясным разделением ролей:

- **IBM Plex Sans** — весь интерфейс. Выбрана не как дефолт: у неё инженерная, телеком-родословная и узкие цифры, она держит плотную таблицу лучше, чем Inter, и не выглядит как любой другой SaaS.
- **IBM Plex Mono** — только числа, которые сравниваются по вертикали: время, длительность, внутренние номера, счётчики в колонках. Не для подписей, не для надзаголовков, не для «стильных» лейблов. Моноширинный шрифт здесь функция (колонки цифр выравниваются), а не приём.

Везде, где числа не в моно, включить `font-variant-numeric: tabular-nums`, иначе счётчики будут дёргаться при поллинге.

Шкала — четыре размера, не больше:

```
24/32 semibold   имя звонаря, заголовок страницы
15/22 medium     заголовки секций
14/20 regular    основной текст и таблица
12/16 regular    подписи и мета
```

Заголовок «Звонари» с 40px до 24px. Иконку в скруглённом квадрате рядом с ним убрать. Описание сервиса убрать со страницы совсем — оно не нужно человеку, который заходит сюда третий раз за день.

Ничего в ALL CAPS. Никаких надзаголовков-эйлбров над секциями. Никаких мета-строк через `·` там, где это просто два отдельных поля.

### Плотность и иерархия

- Один уровень карточек. Внутренние группы разделяются линией и заголовком секции, а не вложенной карточкой с тенью.
- Скругление: 8px у карточек и полей, 6px у бейджей и кнопок. Не 16 и не 24.
- Тени убрать почти везде, оставить только у оверлеев (поповер, дропдаун, шит). Разделение делает `--border`, а не тень.
- Строка таблицы: высота 44px, вертикальный паддинг 8px. Сейчас строки дышат так, будто их пять, а их 50 на странице.
- Чип статистики: одна строка `Фрод 2`, а не коробка с числом сверху и подписью снизу. Число и подпись рядом читаются быстрее и занимают в четыре раза меньше места.

### Кнопки в блоке синхронизации

```
[ Синхронизировать ]  [ Анализировать ]              [ ⋯ Ещё ]
      primary            secondary                      └ Повторить неудачные
                                                        └ ─────────────
                                                        └ Перетранскрибировать на GPU  (destructive)
```

Два частых действия видимы, редкие уезжают в `DropdownMenu`. GPU-прогон получает destructive-стиль и подтверждение из задачи 4 первой части. Даты — через shadcn `Popover` + `Calendar`, чтобы поля и пресеты были одной высоты и одного шрифта.

### Действия на строке звонка

Иконки оставить, но добавить `Tooltip` и `aria-label`: микрофон → «Перетранскрибировать», звёздочка → «Переанализировать». При наведении на строку показывать их ярче, в покое — приглушённо. Во время выполнения — спиннер на месте иконки (задача 15 первой части).

### Движение

Одна анимация: раскрытие строки звонка и переключение таба. `transition-[height]` 150ms, `prefers-reduced-motion` уважать. Никаких появлений секций при скролле и hover-подъёмов карточек — это ровно то, что делает интерфейс похожим на сгенерированный.

## 4. Копирайт

- «Отдельно:» → «Вне скрипта». Это не «отдельно», это исходы, которые не про прохождение шагов.
- «требует внимания» → конкретика: «67% с ошибками» или «36 без анализа». Бейдж должен называть причину, иначе он просто тревожный цвет.
- «Не проанализировано» как исход и «не проанализировано» как статус в колонке «Итог» — это одно и то же, оставить одну формулировку.
- Ошибки писать по делу: не «Ошибка синхронизации», а «OnlinePBX не ответил на 12 записях. Повторить».
- Кнопка и её результат называются одинаково: жмём «Проанализировать» → тост «Проанализировано».

## 5. Порядок работ

1. Роут `/zvonari/:ext` + табы, перенос существующих блоков без изменения логики. Аккордеон удалить.
2. Sticky-шапка звонаря с подписанными метриками (чинит проблему голых чисел).
3. Компонент дорожки скрипта в трёх размерах, замена чипов-стрелок на вертикальную воронку.
4. Токены и типографика в `globals.css`, прогон по всем компонентам страницы.
5. Плотность: паддинги, скругления, тени, высота строк.
6. Кнопки, дропдаун, date picker, тултипы на иконках.
7. Пустые состояния и копирайт.

**Приёмка.** После пунктов 1–3 сделать скриншот страницы звонаря с реальными данными и с нулями и сравнить с текущими: раскрытая карточка должна помещаться в один экран, а не в три. После 4–6 — прогнать всю страницу на 1280px и на 390px.

## 6. Чего не делаем

- Не тащим новую UI-библиотеку и не уходим с shadcn.
- Не рисуем графики и диаграммы поверх воронки — цифр и полос достаточно.
- Не делаем тёмную тему в этой итерации.
- Не трогаем список звонарей структурно, только стиль.
